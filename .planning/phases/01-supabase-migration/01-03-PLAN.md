  <name>Task 1: Create Supabase client modules</name>
  <files>src/lib/supabase/server.ts, src/lib/supabase/client.ts</files>
  <action>
    Create the `src/lib/supabase/` directory with two client modules.

    **Step 1: Create `src/lib/supabase/server.ts` — Server-side client**

    This client runs in Server Components, Server Actions, and Route Handlers. It uses the service role key for full database access (bypasses RLS). This is appropriate because:
    - Drizzle ORM already has full access via direct PostgreSQL connection
    - The Supabase client here is for REST API calls and Realtime admin operations
    - Clerk handles auth, so we don't need Supabase Auth with service role

    ```typescript
    import { createServerClient } from '@supabase/ssr';
    import { cookies } from 'next/headers';

    /**
     * Creates a Supabase client for server-side use.
     * Uses service_role key for admin-level access (bypasses RLS).
     * For user-scoped queries, use the browser client or pass the user's JWT.
     */
    export async function createClient() {
      const cookieStore = await cookies();

      return createServerClient(
        process.env.NEXT_PUBLIC_SUPABASE_URL!,
        process.env.SUPABASE_SERVICE_ROLE_KEY!,
        {
          cookies: {
            getAll() {
              return cookieStore.getAll();
            },
            setAll(cookiesToSet) {
              cookiesToSet.forEach(({ name, value, options }) => {
                cookieStore.set(name, value, options);
              });
            },
          },
        }
      );
    }
    ```

    **Step 2: Create `src/lib/supabase/client.ts` — Browser-side client**

    This client runs in Client Components. Uses the anon key for user-scoped operations (respects RLS).

    ```typescript
    import { createBrowserClient } from '@supabase/ssr';

    /**
     * Creates a Supabase client for browser-side use.
     * Uses the anon (public) key - respects Row Level Security.
     * For Realtime subscriptions and REST API calls from client components.
     */
    export function createClient() {
      return createBrowserClient(
        process.env.NEXT_PUBLIC_SUPABASE_URL!,
        process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!
      );
    }
    ```

    **Step 3: Check if `@supabase/ssr` is needed**

    The `createServerClient` and `createBrowserClient` functions come from `@supabase/ssr`, a separate package from `@supabase/supabase-js`. Check if it's already installed:

    ```bash
    npm list @supabase/ssr
    ```

    If not installed:
    ```bash
    npm install @supabase/ssr
    ```

    **IMPORTANT:** These clients are set up but NOT connected to Drizzle. Drizzle continues to use direct PostgreSQL connection (`getDb()` from `@/lib/db`). These Supabase clients are for:
    - Future Realtime subscriptions (`client.channel('events').on('INSERT', ...)`)
    - REST API access if needed
    - RLS enforcement for user-facing queries (if migrating away from Drizzle for specific operations)
